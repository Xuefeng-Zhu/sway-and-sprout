# MoveNet confidence operating-point pilot — protocol frozen before inference

This is a separate image-level calibration/validation pilot. It can justify a named experimental debug-video gate; it cannot certify a production confidence probability, natural-motion reliability or Fire TV hardware. No inference was performed to design these rules. The legacy .65 route remains unchanged. The [machine-readable protocol](protocol.json) is authoritative for the fixed counts/rules.

## Fixed model and independent data

Calibrate only the pinned Lightning FP16 v4 (`0fac2226…135ab`) with the application's stateless **three-pass image profile**. Use the existing Android `NativeMoveNet`, raw RGB192 input and unchanged model/crop implementation. A different model or tracked temporal-ROI profile requires a separate calibration. Static one-pass resets must not silently stand in for tracking. Established sampled preprocessing parity should not be repeated for this unchanged path.

Use official COCO2017 **val**, never train (training may overlap MoveNet training). Selection uses human labels only: license IDs4/5/8, exactly one annotated person including zero-keypoint/crowd annotations in that count, target noncrowd, at least10 labeled joints, target bbox at least10% of source area, shoulder span at least40px and all4 shoulders/wrists labeled. Freeze **47 visible-primary +6 occluded-challenge calibration images** and **32 visible-primary +3 occluded-challenge heldout images**,53/35 total. The separate no-person challenge is20 calibration/20 heldout images, with both zero annotations and independent model-blind visual absence confirmation. Missing/ambiguous/download failures may be replaced by a frozen next-ranked eligible source only before inference. Preserve every exclusion reason.

All4 primary joints have COCO `v=2`. Challenge `v=1` means labeled but not visible; an accurate inferred joint may legitimately be invisible. `v=0` means no labeled location and cannot be treated as a coordinate error. COCO points are human point estimates, without exact uncertainty rectangles. Do not relabel disagreement after looking at predictions. Source images, exact/near-duplicate families and all crops from a source must stay in one split. Image disjointness does not prove person-identity disjointness; record that limitation.

Freeze recipe, sources, labels, transforms, split, independent absence review and SHA256 manifests before model use. Run calibration53+20 first. Select and freeze one threshold/policy or none, then run/reveal heldout35+20 once. Never choose a fallback threshold from the heldout results. Existing Pexels/DVIDS acceptance controls cannot select a gate.

## What the score and error mean

The raw statistic is `q=min(score[5],score[6],score[9],score[10])`. It is a MoveNet keypoint score, neither MediaPipe visibility/presence nor a measured person-global probability. Do not sigmoid/remap it or inflate a weak raw score to .65. Crop support remains.2 and is unrelated to event admission.

Let `w=hypot(GT_ls-GT_rs)` in original source pixels and each normalized point error be Euclidean prediction-to-human-point distance divided by `w`. A primary image is accurate only when **all4 errors <=.10**. Invalid mappings/nonfinite values fail accuracy; required source dimensions must match the decoded bitmap. Admission is the actual four-point gate: all4 finite/inbounds/native scores in[0,1], positive shoulder span and `q>=tau`, without conditioning on gesture geometry. Report four-joint coverage, each joint's errors/scores and the minimum score. A no-person image admitted by this rule is a **false joint/pose admission**, not a false gesture event. Still images have no dwell history.

PCK within.10 does not guarantee a gesture near a decision boundary. Four joint errors bounded by.10w can change the raise margin by at most.26w and the down margin by at most.24w (including shoulder-width error). Compute the existing.30/.20 signed GT margins; call a geometry label robust only when each needed margin exceeds its corresponding error bound. Otherwise report boundary ambiguity; do not relax margins or rewrite the frozen near-face six-event expectation. Those bounds are relative to annotated point estimates, not a guarantee about unknown annotation uncertainty.

## Threshold selection, frozen numerical rules

Evaluate the18 fixed thresholds .10,.15,…,.95, including the .65 baseline. A candidate must admit at least20 primary calibration images, have `20*incorrect <= admitted` (empirical incorrect fraction <=5%), admit **zero of20 reviewed no-person calibration images**, add zero incorrect occluded challenge admissions versus.65 and gain at least5 correctly admitted primary images versus.65. Among feasible thresholds maximize correctly admitted primary images; break ties with the **higher threshold**. If none qualifies, select none. No post-result adjustment of the grid, metric, limits or counts is permitted.

On heldout data, the single frozen candidate must admit at least15 primary images, add at least5 correct primary admissions versus.65 and **zero new incorrect primary or occluded admissions**, while admitting **zero of20 no-person images**. Report baseline and candidate numerators/denominators, all newly admitted cases, per-joint/PCK/robust-geometry breakdown, occlusion cases and exact intervals. Failure rejects the pilot; it does not authorize selecting another heldout-fitted threshold. The five-correct-gain criterion is an empirical pilot condition, not a universal accuracy claim.

The production evidence criterion remains a one-sided95% upper bound <=5% for both conditional incorrect admission and background false admission at a fixed gate, plus independent temporal/hardware acceptance. This pilot is too small to meet it: even0/32 errors gives upper8.94%;0/20 background admissions gives13.91%. At least59 independent zero-error admissions are needed for a5% bound. These exact Clopper–Pearson bounds assume the stated Bernoulli sampling model; a small curated COCO subset does not represent all deployment people/poses. After grid selection, calibration-set intervals are descriptive, not unadjusted simultaneous guarantees. Do not pool the artificial primary/background prevalence into deployment precision.

## Native execution and integration boundary

A minimal debug-only still batch Activity can use pinned local JPEG assets/manifest and the exact `NativeMoveNet` class, one image at a time. `BitmapFactory` must decode ARGB_8888 with `inScaled=false`, no EXIF autorotation and exact annotated dimensions. No oracle GT bbox crop or per-image fitting. Reset before each independent image, run3 passes and log all outputs regardless of score. Emit only scalar source/image IDs, model/profile, raw four scores, restored four coordinates, invalid flags, dimensions and timing. Recycle bitmaps and close the interpreter in `finally`; no WebView events, saved participation, synthetic holds, camera or upload. This proves Android static-image extraction only, not actual game scoring or temporal tracking.

If the pilot is justified, integrate an explicit **debug-video-only** policy pinned to the model SHA, image3 profile, threshold, data/protocol/calibration hashes and a known policy ID. `PoseGestureMachine` currently checks.65, and **`src/motion.js:46` separately checks.65**. Both need a validated model-specific route; arbitrary packet/intent thresholds must not bypass the legacy route. Keep event confidence equal to its raw minimum, with clearly named policy metadata. A policy change midway through a round invalidates the context. Camera, synthetic, release, default OpenCV and optional MacFull keep existing behavior. `NativePoseDiagnostics:34` also hardcodes.65; active-policy counters must be correct and baseline counters retained separately.

Before calling an experimental application improvement, preserve actual frontal6 events/6rays/ACK6, complete negative controls, independently annotated heldout natural positives and hard negatives, loss/both-up/wrong-side cases, real timer, pause/revision/epoch/lease/ACK protection, lifecycle and nonempty saved progress. All geometric/timing rules remain unchanged. Full-file model/gesture analysis and actual30-second UI coverage must be reported separately; the previous image3 long-negative timeout remains a performance failure. A static-image pilot cannot erase it. No physical Fire TV is available, so FireOS/32-bit execution/UVC/sustained resource claims remain open.
